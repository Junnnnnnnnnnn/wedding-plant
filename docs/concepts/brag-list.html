목록 화면

A안으로 정했습니다. 카드는 커플과 날짜로 시작하고, 배치는 핀터레스트식 벽돌입니다. 여기서는 목록 화면 하나만 실제 크기로 봅니다 — 흐름 전체는 A안 문서에 있습니다.

웹

벽돌 3열

좌측 레일의 둘러보기 묶음, 피드 아래입니다. 아래는 레일을 뺀 본문만 실제 크기로 그린 것입니다 — 셸까지 넣으면 1440px 이라 문서 폭에 안 들어가고, 줄이면 카드 글자가 9px 이 돼 판단이 안 됩니다.

자랑하기

먼저 준비한 커플들의 플랜 128개

무한 스크롤을 쓰지 않습니다. 벽돌 배치는 카드가 붙을 때마다 단 높이가 다시 잡혀서, 스크롤 중에 밑에 있던 카드가 위로 튑니다. 누르려던 카드가 손가락 아래에서 바뀌는 게 이 화면에서 가장 나쁜 일입니다 — 더 보기로 사람이 시점을 정합니다.

정렬은 셋입니다 — 최신 · 좋아요순 · 낮은 예산순. 카테고리 필터는 두지 않습니다. 자랑하기의 단위가 플랜 전체라 한 플랜에 카테고리가 네댓 개씩 걸려 있어서, 필터를 걸어도 목록이 거의 줄지 않습니다.

모바일

벽돌 2열

머리 면은 스크롤 영역 안에 있어 내용과 함께 위로 올라갑니다 (앱의 다른 화면과 같은 규칙). 카드는 카테고리 칩을 접습니다 — 2열이면 카드 폭이 180px 쯤이라 "예물 · 예단" 같은 칩이 한 줄에 하나씩 떨어져 카드가 칩 목록이 됩니다.

자랑하기

먼저 준비한 커플들의 플랜 128개

홈피드자랑참여설정

정렬 칩은 가로로 흐릅니다(.c-chips) — 앱의 피드가 이미 그렇게 씁니다. 폰에서 셋을 억지로 한 줄에 욱여넣으면 글자가 10px 이 됩니다.

탭바가 다섯 칸이 됩니다. 지금 넷(홈 · 피드 · 참여 플랜 · Settings)에 자랑이 들어갑니다. "더보기" 뒤로 숨기면 새로 만든 화면을 아무도 못 찾습니다.

카드 하나를 누르면 모달이 뜹니다. 폰에서는 여백 규칙이 16px 까지 줄어 사실상 전체 화면입니다.

상태

목록이 실제로 겪는 것

카드가 찬 화면만 그리면 배포하고 나서 나머지를 급히 만듭니다. 이 화면이 실제로 겪는 상태는 넷입니다.

아직 올라온 플랜이 없어요.
우리 플랜을 올리면 여기 맨 앞에 놓입니다.

④ 못 불러왔을 때

목록을 못 불러왔어요

잠시 문제가 생겼습니다.
다시 시도하면 대부분 해결됩니다.

①의 권유 줄은 목록을 밀어내지 않습니다 — 한 줄짜리 띠고, 올리고 나면 사라집니다. 피드에서 배운 것입니다: 카드로 만들어 목록 위에 얹었더니 보러 온 후기가 한 화면 아래로 밀렸습니다.

③과 ④는 다른 화면입니다. "비었다" 와 "못 불러왔다" 를 같은 말로 쓰면, 서버가 죽었을 때 사용자가 "아무도 안 올렸구나" 하고 나갑니다.

앱에서 그대로 가져오는 것

카드의 예산 막대는 홈·참여 플랜과 뜻이 같습니다 — 분홍은 실제로 나간 돈, 회색은 아직 안 쓴 예정, 남은 트랙이 여유. 자랑하기라고 색의 뜻을 바꾸지 마세요.

내 카드

좋아요 자리에 "내 플랜" 이 들어갑니다. 내가 내 것에 좋아요를 누를 수는 없으니 그 자리를 비워 두느니 어느 게 내 것인지를 말합니다. 정렬과 무관하게 맨 앞에 고정하지 않습니다 — 최신순이면 올린 시각대로 놓입니다.

아직 안 정한 것

좋아요를 누른 목록을 따로 볼 수 있어야 하나요? 있으면 "나중에 참고할 플랜"을 모으는 자리가 되는데, 그건 자랑하기가 아니라 스크랩이라 성격이 다릅니다. 1차에서는 넣지 않았습니다.
