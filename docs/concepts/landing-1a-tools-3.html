셋을 나란히

시안 말하는 방식 셰이더가 그리는 것 약한 점
A 도구마다 한 화면씩 섹션 안에 네 소섹션. 왼쪽은 늘 지금 쓰는 도구, 오른쪽은 늘 앱. 컴퓨터 도구는 브라우저 창, 폰 도구는 폰 프레임 없음 — 프레임 안 화면이 주인공이라 배경이 움직이면 방해가 됨 셋 중 가장 김(4.6화면). 목업 8개를 계속 손봐야 함
B 하나로 접힘 도구가 하나씩 쌓였다가, 카드가 채워지는 동안 흐려짐 흩어진 점이 카드 쪽 한 점으로 빨려듦 오른쪽 카드가 여전히 기능 나열이라 앞 섹션과 겹칠 여지
C 문장만 문장이 한 줄씩 놓이고 마지막에 결론 먹이 번져 나감 — 조용하고 글을 안 가림 시각 요소가 없어 스크롤이 빨라짐

A 로 가되, 길이를 감당할 수 있을 때만

A가 설득력은 가장 큽니다. “엑셀은 폰에서 불편합니다”라고 말하는 대신 잘린 스프레드시트를 보여줍니다 — 결혼 준비를 해본 사람은 저 화면을 안 봐도 압니다. 네 도구를 다 아는 사람이라 이 넷 중 하나에라도 걸립니다. 대신 이 섹션 하나가 4.6화면이 되고, 앞의 두 핀 섹션까지 더하면 랜딩이 길어집니다.

C는 반대 선택입니다. 이 섹션은 CTA 바로 앞이고 앞 두 섹션이 이미 화면을 잔뜩 보여줬으니, 여기서는 눈을 쉬게 하고 논지만 남기는 게 맞다는 판단입니다. 랜딩 전체 길이가 걱정되면 C 입니다.

B는 앞에서 “여러 개 → 하나”를 이미 말했다면 중복입니다.

섞을 수도 있습니다 — A 를 두 개(엑셀·카카오톡)로 줄이고 나머지 둘은 C 의 문장으로 처리하면 2.5화면에 설득력은 대부분 남습니다.

셋 다 1020px 아래에서는 핀을 걸지 않습니다 — 세로로 쌓이면 한 화면보다 커져 잘립니다. 그 폭에서는 평범하게 흐르고 모든 요소가 그대로 보입니다.
